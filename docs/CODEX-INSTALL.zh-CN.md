# 让本机 Codex 帮你安装 Workbench

这是供你自己的 Codex 阅读的安装说明。仓库只提供通用程序，不包含作者的服务器、聊天记录、业务文件、密码或 Claude/Codex 登录状态。每个人使用自己的服务器和账号；已经登录好的 CLI 可继续使用。

## 给 Codex 的任务

把这份页面的链接发给本机 Codex，并说明：

> 请按这份说明帮我安装自己的 Workbench，使用 personal 分支的最新代码。先检查我的电脑和现有 SSH 连接；缺少服务器地址、登录用户或要同步的文件夹时再问我。保留现有数据和账号登录状态，完成后实际验证网页、模型会话和文件同步。不要连接仓库作者的服务器。

## Codex 执行时的顺序

1. **确认安装对象。** 检查本机 Git、Node.js 和现有 SSH 配置。服务器尚未购买时，先说明需要的服务器信息；不要默认购买资源或把一份新安装覆盖到已有服务。使用用户提供的 SSH 连接，保留原有条目并核验主机身份。密钥与密码留在本机或服务器私有配置中，不写入仓库或聊天输出。
2. **取正确的版本。** 克隆 `https://github.com/zhangyc-413/workbench-personal.git` 的 `personal` 分支，记录 `git rev-parse HEAD`。`main` 是上游代码，旧标签 `v0.4.0-personal.1` 不含后续新增的连接、缓存及恢复功能。已有修改的目录先检查，不强制覆盖。
3. **读实际安装契约。** 先读根目录 `AGENTS.md`、`README.md`、`docs/ARCHITECTURE.md`、`docs/PERSONAL-SETUP.zh-CN.md` 和 `docs/OPERATING-GUIDE.md`。需要 Mac 文件同步时再读 `docs/COMPUTER-CONNECT.md`；域名与网页登录可参考 `modules/remote-access/README.md` 及其模板。文档中 `xxxxx` 只是占位符。
4. **先跑通独立服务器。** 根据实际环境安装固定 Node.js 22 依赖，用专门系统用户运行 Home 和 Worker。源码、状态数据、项目文件分开。先从本机 SSH 转发验证；需要域名时，再配置有身份验证的 HTTPS 入口。模型 CLI 在运行 Worker 的同一个系统用户下检查登录；缺登录时让用户完成官方验证，不复制作者或另一人的凭据。
5. **只连接选定文件夹。** 用户需要同步时，准备专用 Syncthing 和受限 SSH 转发账户，按 COMPUTER-CONNECT 契约配置。只创建用户选定的独立文件夹对，说明文件修改和删除会双向同步；保留冲突副本，不覆盖既有同步关系。电脑离线时本机暂停同步，重新上线后继续。
6. **本机也能修改功能。** 用户明确选择后，提供独立的本地源码目录及维护 SSH，按现有维护工具检查、测试、备份和发布。源码修改不应通过业务文件同步直接覆盖运行中的程序；不要把业务文件或登录状态提交 Git。
7. **验收后交付。** 运行仓库要求的检查，验证 Home/Worker 状态、浏览器实际打开和一次模型会话。需要同步的安装，应在用户选定的专用目录中用可删除的测试文件验证两个方向，清理测试文件，并检查后台自动启动。测试失败就说明失败点，不以进程启动代替成功。最后给用户网页地址、使用方法及私有配置所在位置，密码不要写进公开文件。

## 已有工作台，只需要连接 Mac

若服务端已经配好，点网页的 **连接我的电脑 → Codex 连接 → 用 Codex 连接 → 打开 Codex 继续**。浏览器会准备带校验值的短期连接资料并填好 Codex 任务；在 Codex 中发送后，再选择文件夹。不能唤起应用时，点击 **复制任务**。

不要把含短期连接凭据的下载包当作 GitHub 安装包转发。朋友应从自己的工作台获取自己的资料。网页链接只填任务，不会自动发送或绕过本机权限；未经 Apple 公证的旧 `.command` 助手仍可能被 macOS 阻止。
